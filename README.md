# Job Tracker

Локальный трекер вакансий с браузерным расширением-коллектором. Предназначен для личного использования в локальной сети: вакансии сохраняются в SQLite на своём сервере, а расширение захватывает страницу только по явному нажатию **Save Job**.

## Что умеет

- Сохранять вакансии из LinkedIn, Greenhouse, SmartRecruiters, SuccessFactors, Workday и других сайтов.
- Хранить исходный безопасный DOM-снапшот вместе с разобранными полями. После обновления парсера вакансию можно переразобрать без повторного посещения сайта.
- Показывать вакансии таблицей, канбан-доской или архивом; группировка работает в таблице и канбане.
- Перетаскивать карточки между этапами: «Сохранено», «Отправлено», «Интервью», «Результат».
- Вести таймлайн откликов и интервью: `Applied`, `HR screening`, `Technical interview`, `Final interview`, `Follow-up`.
- Сворачивать этапы канбана; высота колонок зависит от содержимого, а оставшиеся колонки расширяются. Есть отдельный компактный вид карточек.
- Фильтровать, сортировать и группировать вакансии по тегу, компании, локации, источнику и месяцу добавления. Настройка представления хранится в URL и браузере.
- Создавать теги вручную или предложить до пяти тегов через AI.
- Показывать в настройках столбчатую статистику подач по дням: день, неделя, месяц или всё время от первой подачи.
- Подключать AI-провайдеры для сопоставления вакансии с профилем кандидата, предложений тегов, классификации почты и структурного разбора Generic-карточек.
- Запускать в поп-апе редактирования ручной AI-разбор Generic snapshot: AI предлагает позицию, компанию, локацию, формат работы и занятость; пользователь проверяет поля перед сохранением.
- Синхронизировать две выбранные IMAP-папки — «Интервью и screening» и «Отказы» — в режиме только чтение: классифицировать входящие письма, предложить вакансию и обратимо применить подтверждённый отказ. Письма с адреса IMAP-пользователя не сохраняются и не отправляются в AI.

## Архитектура

| Часть | Назначение |
| --- | --- |
| `server/` | Fastify API, SQLite, парсеры, хранение снапшотов и AI-интеграция |
| `web/` | Интерфейс трекера: `/`, `/jobs/:id`, `/settings`, `/stats` |
| `extension/` | Chrome/Chromium Manifest V3-расширение для ручного сохранения вакансий |
| `shared/` | Общие схемы и типы |

Снапшоты, вакансии, события, теги, AI-настройки и загруженный профиль хранятся в SQLite. Отдельное облако, Redis или PostgreSQL не требуются.

## Roadmap

- Декларативный реестр простых ATS-адаптеров: настраиваемые домены и CSS-селекторы, preview на сохранённом snapshot и повторный разбор без AI.
- Версии и fixtures адаптеров, чтобы замечать деградацию DOM и безопасно откатывать изменения.
- Сложные источники останутся TypeScript-адаптерами; повторяющиеся Generic-сайты можно будет перенести в реестр после проверки.

## Быстрый запуск через Docker Compose

1. Скопируйте `.env.example` в `.env` и задайте два случайных длинных значения:

   ```dotenv
   API_TOKEN=replace-with-a-long-random-token
   AI_SECRETS_KEY=replace-with-another-long-random-secret
   ```

   `API_TOKEN` нужен расширению для импорта снапшотов. `AI_SECRETS_KEY` шифрует ключи AI-провайдеров в SQLite. Если не задать второй ключ, для шифрования будет использован `API_TOKEN`.

2. Настройте адрес публикации в `.env`:

   ```dotenv
   # Только на самом сервере
   BIND_IP=127.0.0.1

   # Или конкретный LAN-адрес хоста, например 192.168.1.100
   # BIND_IP=192.168.1.100
   PORT=3000
   ```

3. Запустите сервис:

   ```bash
   docker compose up -d --build
   ```

4. Откройте `http://<IP-сервера>:3000`.

Данные сохраняются в именованном Docker volume `job-tracker-data`. Обновление образа не удаляет базу.

### Установка через Portainer из Git-репозитория

В Git-стеке файла `.env` обычно нет. В Portainer откройте **Stack → Environment variables** и задайте как минимум:

```text
API_TOKEN=<длинный случайный токен>
AI_SECRETS_KEY=<другой длинный случайный ключ>
BIND_IP=<LAN IP сервера или 127.0.0.1>
PORT=3000
```

Если Docker сообщает, что порт уже занят, измените `PORT` на свободный, например `3006`, и используйте этот порт в адресе сайта и настройках расширения.

## Локальная разработка

Нужен Node.js 20+ и npm.

```bash
npm install
cp .env.example .env
npm run build
npm run dev
```

Для запуска без `.env`:

```bash
API_TOKEN=dev-token npm run dev
```

По умолчанию база создаётся в `./data/jobs.db`; директория будет создана при запуске.

Проверки:

```bash
npm test
npm run build
```

## Установка расширения

1. Соберите проект: `npm run build`.
2. В Chrome/Chromium откройте `chrome://extensions`.
3. Включите **Developer mode**.
4. Нажмите **Load unpacked** и выберите папку `extension/`.
5. Откройте настройки расширения, укажите адрес сервера, например `http://192.168.1.100:3000`, и тот же `API_TOKEN`.
6. Нажмите проверку соединения. Chrome запросит разрешение только для указанного адреса сервера.

На странице вакансии нажмите иконку расширения и **Save Job**. Для Greenhouse, SmartRecruiters, SuccessFactors, Workday и других поддержанных источников расширение выбирает специализированный контейнер. На другом сайте предварительно выделите блок вакансии: Generic-коллектор возьмёт выделение; если его нет — `main` или `article`, но никогда весь `body`.

Если сервер временно недоступен, безопасный снапшот остаётся в IndexedDB расширения и его можно отправить повторно без возвращения на сайт вакансии.

## Работа с интерфейсом

### Канбан

- Перетащите карточку в другую колонку, чтобы сменить этап.
- Кнопка у заголовка колонки сворачивает этап в узкую вертикальную полосу с количеством вакансий. Повторный клик разворачивает его.
- Иконка плотности карточек в панели доски включает компактный вид. В нём остаются позиция, компания, локация, AI-индикатор и предупреждение об ожидании; подробности открываются кликом по карточке.
- В меню **Группировать** создаются несколько независимых досок — например, по тегу или локации. Без группировки остаётся одна доска по этапам.

### Карточка вакансии

Карточка открывается без перезагрузки. В ней можно:

- исправить название, компанию, локацию, тип занятости и ссылку;
- менять этап и подэтап интервью;
- вести заметки и таймлайн;
- добавлять и удалять теги;
- запускать AI Match;
- для Generic-карточки запускать AI-разбор прямо в поп-апе редактирования: результат только заполняет форму и применяется после обычного сохранения;
- переразобрать сохранённый DOM-снапшот после улучшения парсера.

Жёлтая индикация появляется после 14 дней без события, красная — после 35 дней.

### Настройки

На `/settings` находятся:

- IMAP-подключение, ручная синхронизация и очередь проверки писем;
- резервные копии, восстановление и Google Sheets webhook;
- реестр тегов и их цвета;
- JSON-профиль кандидата;
- список AI-подключений и отдельные defaults для Match, тегов, почты и структурного AI-разбора.

На `/stats` находится отдельная рабочая страница статистики: динамика откликов, воронка «отклик → HR/интервью → оффер», доля вакансий без ответа более 16 дней, а также эффективность по источникам, тегам и калибровка AI Match. Каждая вакансия учитывается один раз по первому событию `applied`; малые группы явно отмечаются как недостаточные для вывода.

## AI: профиль и провайдеры

AI-функции необязательны. В настройках можно создать подключение к Mistral, OpenAI, Google Gemini, Ollama или OpenAI-compatible API, указав URL, модель, ключ, таймаут, лимит output tokens и лимит запросов в минуту для разбора почты. У одного подключения можно назначить отдельную роль: **Match**, **Теги**, **Почта** или **Разбор**. Для Generic AI-разбора используется роль «Разбор», а если она не задана — provider для Match.

Профиль кандидата можно загрузить JSON-файлом в настройках. Для Docker также поддерживается файл из `.ai/`, смонтированный в контейнер только для чтения. Загруженный профиль хранится в persistent volume и имеет приоритет над файлом.

При первом AI Match для каждого провайдера интерфейс попросит подтвердить передачу профиля. В AI Match отправляются текст вакансии и профиль. Для ручного Generic-разбора в AI отправляется сохранённый текст snapshot без профиля. Браузерное расширение не обращается к AI-сервисам и не получает ключи провайдеров.

## IMAP-синхронизация

Настройте её в разделе **Почта** на странице настроек. Пароль приложения вводится в форме, тестируется до сохранения и хранится в SQLite только в зашифрованном виде; переменные окружения для адреса или пароля почты не нужны. Выберите отдельное AI-подключение меткой **«Для почты»** в настройках AI либо будет использован provider для AI Match.

Синхронизатор открывает папки «Интервью и screening» и «Отказы» по очереди в read-only режиме только после явного нажатия **«Синхронизировать»**: не меняет флаги, не помечает письма прочитанными, не переносит и не удаляет их. Для каждой папки хранится отдельный IMAP-курсор. Сообщения, отправленные с IMAP-адреса пользователя, отбрасываются до сохранения и AI-классификации. AI-запросы для писем равномерно ограничиваются лимитом RPM выбранного провайдера (по умолчанию 10); ответ 429 оставляет конкретное письмо в очереди, не прерывая синхронизацию папки. Для входящих писем сохраняется очищенный текст тела и технический IMAP-ключ дедупликации; вложения, адреса, MIME-заголовки и HTML не хранятся. Первичная загрузка всегда идёт в очередь проверки. Для новых писем можно включить автоматическое применение только точных отказов. Любое применённое email-решение можно отменить, если карточка вакансии после него не менялась вручную.

## Приватность и безопасность

- Расширение ничего не собирает в фоне: не скроллит страницу, не нажимает элементы, не читает cookies, токены или локальное хранилище сайта.
- Снапшот берётся только после явного нажатия **Save Job**.
- HTML очищается в расширении и повторно на сервере. В интерфейс выдаётся только безопасная версия описания.
- Сервер не делает запросов к карьерным сайтам и не использует headless-браузер.
- Веб-интерфейс намеренно открыт для устройств, имеющих доступ к вашему LAN-серверу. Поэтому не публикуйте порт в интернет; для удалённого доступа используйте HTTPS и отдельный reverse proxy/VPN.
- Bearer-токен защищает импорт расширения. Храните его как секрет и не добавляйте `.env` в Git.

## Резервная копия

В **Settings → Общее → Резервные копии** доступны два скачиваемых формата:

- **JSON** — переносимый полный снимок данных: вакансии, DOM-снапшоты, события, теги, AI-анализы, история писем и JSON-профиль кандидата. В него намеренно не попадают API-ключи, IMAP-пароль и секрет webhook.
- **CSV** — компактная таблица вакансий для Excel, Numbers или ручного анализа.

Для аварийного восстановления самого сервера дополнительно сохраняйте именованный Docker volume `job-tracker-data` (или `data/jobs.db` при локальном запуске). В нём остаются зашифрованные настройки подключений, которые не экспортируются в JSON.

JSON можно восстановить в том же блоке настроек: сначала приложение покажет состав файла, затем попросит подтвердить замену данных. Восстановление заменяет вакансии, снапшоты, события, теги, историю писем и AI-анализы. Пароли и ключи провайдеров намеренно не восстанавливаются; существующие локальные подключения и их секреты сохраняются. Импортированные AI-подключения без ключей добавляются выключенными, чтобы ничего не отправилось автоматически.

### Google Sheets без Google API

Трекер умеет отправлять синхронизацию в **Google Apps Script Web App** обычным HTTPS webhook. Это не требует Google API, OAuth или доступа приложения к вашему Google-аккаунту. В Sheets уходят только компактные листы `Jobs`, `Events`, `Tags`, `Emails`; HTML-снапшоты и тела писем не передаются.

1. Создайте Google Sheet → **Extensions → Apps Script**.
2. Вставьте код ниже. При желании задайте один и тот же секрет в `WEBHOOK_SECRET` и в настройках трекера.
3. Нажмите **Deploy → New deployment → Web app**, запускайте от своего аккаунта и дайте доступ, подходящий вашей схеме. Скопируйте URL, оканчивающийся на `/exec`.
4. Вставьте URL в **Settings → Общее → Резервные копии**, сохраните и нажмите **Синхронизировать сейчас**. Там же можно включить периодическую синхронизацию.

```javascript
const WEBHOOK_SECRET = ''; // необязательно: одинаковое значение в Job Tracker

function doPost(event) {
  const payload = JSON.parse(event.postData.contents);
  if (WEBHOOK_SECRET && payload.webhook_secret !== WEBHOOK_SECRET) {
    return ContentService.createTextOutput('forbidden');
  }
  const book = SpreadsheetApp.getActive();
  Object.entries(payload.sheets || {}).forEach(([name, rows]) => {
    const sheet = book.getSheetByName(name) || book.insertSheet(name);
    sheet.clearContents();
    const keys = [...new Set(rows.flatMap(row => Object.keys(row)))];
    if (!keys.length) return;
    sheet.getRange(1, 1, 1, keys.length).setValues([keys]);
    const values = rows.map(row => keys.map(key => row[key] == null ? '' : String(row[key])));
    if (values.length) sheet.getRange(2, 1, values.length, keys.length).setValues(values);
    sheet.setFrozenRows(1);
  });
  return ContentService.createTextOutput(JSON.stringify({ ok: true }))
    .setMimeType(ContentService.MimeType.JSON);
}
```
